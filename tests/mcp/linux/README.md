# Linux MCP contract and launcher checks

These tests build the production MCP helper and GUI-free Agent tests on Linux.
They reuse the actual CMake targets. The `OrcaSlicer` target in this fixture is
only a file-location anchor; it is not the native application and is not run.
The repository is mounted read-only, build artifacts go to a fresh temporary
directory, and tests run as a non-root user so permission checks remain valid.

From the repository root on a Docker host, after generating a normal version header:

```sh
docker build -t jusprin-mcp-linux-test:local -f tests/mcp/linux/Dockerfile tests/mcp/linux
mcp_test_workdir=$(mktemp -d /tmp/jusprin-linux-mcp-XXXXXX)
docker run --rm --user "$(id -u):$(id -g)" \
  --mount "type=bind,source=$PWD,target=/repository,readonly" \
  --mount "type=bind,source=$mcp_test_workdir,target=/work" \
  jusprin-mcp-linux-test:local sh /repository/tests/mcp/linux/run.sh \
  /repository /work /repository/build/arm64/src/libslic3r/libslic3r_version.h
```

Replace the version-header argument with the location generated by your normal
CMake build. Use a new temporary directory for each fresh run. The script runs
the complete Agent suite and Python process/launcher tests. It needs no account
credentials, GUI, external AI requests, or changes to saved client settings.

## Compressed AppImage transport test

The optional `JUSPRIN_TEST_APPIMAGETOOL` setting enables a test that creates a
real compressed Type 2 AppImage containing the production helper and generated
launcher. Supply the official appimagetool executable for the container's
architecture; the project's release packager downloads it from
`https://github.com/AppImage/appimagetool/releases/download/continuous/`.
Record its checksum because that URL changes over time.

After the build above, with the tool saved in the same temporary directory:

```sh
docker run --rm --user "$(id -u):$(id -g)" \
  --mount "type=bind,source=$PWD,target=/repository,readonly" \
  --mount "type=bind,source=$mcp_test_workdir,target=/work" \
  -e JUSPRIN_TEST_BRIDGE=/work/build/jusprin-mcp \
  -e JUSPRIN_TEST_APPIMAGETOOL=/work/appimagetool-aarch64.AppImage \
  -e PYTHONDONTWRITEBYTECODE=1 \
  jusprin-mcp-linux-test:local python3 -m unittest discover -s /repository/tests/mcp -v
```

The test uses extraction mode, requiring no FUSE device or privileged container.
It checks legacy initialization, the real five-tool catalog, discovery of a
controlled HTTP peer, and offline results before/after the peer's lifetime.
Other tests verify ordinary GUI-argument forwarding with a stub, paths with
spaces/Unicode, and failure when packaging cannot find the helper.

This is **not** a full Orca/JusPrin GUI AppImage, release dependency audit,
FUSE-mounted run, Windows test, or AI-client interoperability proof. Those
remain separate acceptance gates. A passing transport fixture must not be
reported as passing the full Linux release scenario.
