## 5. Network calls

- No HTTP GET exists in the Agent code, and nothing fetches a model list. The setup check is a streaming POST through `ProviderAgent`.
- `IAgentHttpTransport` has only `post()` and `cancel()` (`AgentTransport.hpp:48-55`).

- **Async pattern A (the Agent's):** `OpenAIHttpTransport` (`OpenAIHttpTransport.cpp:17-69`) uses `Http::post(...).perform()` with callbacks that hold a `weak_ptr` to state behind a mutex.
  1. `ProviderAgent::accept_http` queues the events under `m_mutex` (`ProviderAgent.cpp:301-305`).
  2. `poll()` / `parse_available()` drains them on the GUI thread (`:439-488`).
  3. The driver is the shell's 33 ms runtime timer (`ShellController.cpp:514`), which calls `pump_stream` / `pump_tools` / `pump_setup` (`:207-211`). PrinterPanel has its own pump (`PrinterPanel.cpp:389`).
- **Async pattern B (the GET example):** `HostLaneReader.cpp:84-106` runs `Http::get(...).perform_sync()` on a detached `std::thread` (`:155-161`). Results go into a shared `HostReadings` that the GUI polls (`host_status`, `:146-164`). Exit safety comes from `StopReadsAtExit` (`:20-49`).
