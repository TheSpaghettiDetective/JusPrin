Kenneth decided the three open print-history questions in a forked session; please update gcode-print-history-handoff.md accordingly (keep it untracked).

Decisions, in Kenneth's words "go with your recommendations":

1. G-code hash = a hash of the G-code file bytes, computed at export or send time (before the file leaves). The existing manufacturing_input_hash is kept beside it as the link to the checkpoint. Display stays eight hex digits in two groups.

2. G-code bytes for Print again: JusPrin keeps a copy of every sent or exported G-code in the project's aux directory next to the checkpoints, with a cap (last N G-codes per project, N to be chosen in code) and a "file no longer kept, re-slice" state for older entries.

3. Record shape: one G-code record holding its lists of destinations (exports, sends) and prints. Export and send both create-or-append. The separate SentRecord / PhysicalPrintRecord events are replaced, not kept beside it; since nothing in the app ever wrote them, there is nothing to preserve beyond a migration note for 3MFs that carry them.
