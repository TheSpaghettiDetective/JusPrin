## The design you are implementing

Kenneth's rule for the project chat: the standing system prompt carries principles only, and everything situational arrives as a skill, a short text the app adds to one request when it knows the situation holds. The app chooses the skill by event; the model never picks one from an index and there is no tool to read one. Four skills are planned; this is the first and it also builds the loading mechanism the other three will reuse: (1) a model is opened or imported; (2) slicing finished unsuccessfully; (3) OrcaSlicer reported a print issue, including the canvas buttons "Explain this issue and my options." and "Help fix this issue."; (4) the project setup changed after a purpose was recorded.
