4. The detached thread. Acceptable, with two facts to design around. Http's DEFAULT_TIMEOUT_MAX is 0 (Http.cpp line 104), so a listener that accepts and never answers holds test() open with no upper bound; only the connect timeout (10 s) is bounded. Our 30-second deadline reports the failure, but the thread lives on. And CurlGlobalInit runs curl_global_cleanup from a static destructor at exit (Http.cpp line 81), so a detached thread still inside curl at exit is a possible exit-time crash, which would reach Sentry. So: detach; the thread owns everything it uses (config copy, PrintHost, a shared result slot tagged with the attempt number); a late result is dropped; do not join in the backend destructor, since a join can stall panel close for as long as the server dawdles. Accept the exit case: the never-answering listener is a test fixture, and real failures resolve inside the 10-second connect timeout.
