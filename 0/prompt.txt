## 2. How it behaves

- **Where projects are stored:** `&lt;data_dir&gt;/jusprin/projects/&lt;project-id&gt;/` (`ShellController.cpp:438-442`).
- **When autosave saves.** A timer runs every 33 ms (`:715`). Autosave checks for changes every 2 s. It saves the model 1.5 s after the last edit, but not while a tool edit is in progress or an AI turn is running. Chat-only changes are written within 15 s at most (`Workspace/ProjectAutosave.cpp:39-41, 632-684`).
- **Blank projects are never saved.** A project is saved once it holds a model, and stays saved after that (`ProjectAutosave.hpp:112-114`). An unnamed project takes its first object's file name (`ProjectAutosave.cpp:547-552`).
- **How many versions are kept:** up to 200 versions or 4 GB. Pinned versions are kept regardless: Save, Restore and AI before/after versions (`ProjectAutosave.cpp:42-43`, `Workspace/ProjectVersionStore.cpp:943-992`).
- **What Restore does.** It saves the current state first, pins both versions, reloads the chosen model and settings, keeps the chats, and brings marked regions back with the model. It adds an undo boundary named "Restore project version" (`ProjectAutosave.cpp:1087-1152`).
- **Export** saves first, then writes through a temporary file (`:1215-1235`). It leaves out the chat state (inferred from harness check `exported_archive_excludes_managed_state`, which tested OrcaSlicer's export path).
- **Files opened from Finder/Explorer, Open… or a drop on Home** open as a new project (`ShellController.cpp:1019-1072`).
  - A Home drop is first copied to `&lt;temp&gt;/JusPrin-dropped/&lt;md5&gt;/` and is left out of recent files (`OrcaHomeBackend.cpp:1395-1437`).
  - If that copy fails: "%s couldn't be opened. Try opening it with Open… instead."
- **A model dropped on the canvas** is added to the open project (`ShellController.cpp:262-290, 1074-1080`).
- **A .3mf opened anywhere** (including a drop on the canvas) opens as a project. If it was opened before, a "Previously opened file" dialog asks. Its buttons are "Continue current project", "Open existing project" or "Open most recent project", and "Create new project". If the file has changed since, "Create new project" becomes the default (`ShellController.cpp:575-650`).
- **After a restart** JusPrin starts on a blank project; nothing reopens on its own (`SH:3119-3130`).

## 2. Behaviour facts
- **Slice vs Print:** the button says Slice until the *current plate* has a valid slice, then Print (PrimaryPrintAction.hpp:30-37). Switching to an unsliced plate brings Slice back.

- **Print all plates…** is enabled only for Bambu or SimplyPrint hosts (lines 220-226).
- **Ignore this warning:**
  - Works only on warnings, never on blockers. The warning stays in the list, marked "Ignored", sorted last, left out of the count and off the pager (IssueOverlay.cpp:593-643).
  - It lasts until Orca stops reporting that warning, so a warning that comes back shows again. It is also cleared when another project opens (J/PrintIssues/PrintIssue.hpp:121-126; PrintIssueMonitor.cpp:264).
  - It does not survive closing the app; this is inferred from the in-memory map at PrintIssueMonitor.hpp:151.
  - To undo it, open the warning from the list and press "Stop ignoring".
- **Print report:** offered only when signed in to a cloud account (OrcaHomeBackend.cpp:1269-1271). It is limited to one per G-code, and none while that G-code is printing (PrintHistory.tsx:136). ## 2. Behaviour facts

- **No printer chosen:** "Printer settings…" opens the Add a printer chat, and "Calibrate…" is disabled (`PrinterMenu.cpp:219-245`; `AppMenus.cpp:492-512`).
- **Skipping first launch** sets up a stand-in "Generic printer" (Generic Klipper, 0.4 mm nozzle) (`OrcaHomeBackend.cpp:920-922`). Home then explains: "Until you add yours, files are sliced for a 250 mm Klipper printer…" (`Onboarding.tsx:27`).
- **Connection types:** Bambu Lab over LAN or Cloud (`OrcaHomeBackend.cpp:244`), Moonraker and OctoPrint (`OrcaPrinterBackend.cpp:825-850`). Any other type gets "…which this chat does not connect…" (`:587-588`). Bambu printers need Bambu's network plug-in ("Bambu plug-in needed", `PrinterPanel.tsx:109`).
- **Removing a printer:** projects stay. It is refused if other printer profiles are based on this one (`Printers/NamedPrinters.cpp:251-253`). Removing a custom printer also deletes its filament and process profiles, through OrcaSlicer's confirm (`:256-268`). Removing the selected printer selects its parent profile (`:270-278`).
- **Rename rules:** the name cannot be empty, cannot contain `&lt; &gt; [ ] : / \ | ? * "`, cannot differ from the old one only in capitalisation, and cannot match another printer's name (`PrinterMenu.tsx:21-29`).
- **Import:** copies printers with their filaments and print settings; the other app keeps its own copy (`Onboarding.tsx:277`). Sources are the OrcaSlicer data folder or JusPrin 1's "JusPrin" folder (`Home/OrcaImporter.cpp:129-134`). JusPrin 1 also brings Bambu's network file; its own app settings and sign-in never come along (`V1Import/V1Import.hpp:5-23`).
