Background (from the session that started this one):
JusPrin is a fork of OrcaSlicer with an in-app LLM agent. Today the agent talks to one API, OpenAI's Responses API, through OpenAIResponsesAgent (613 lines), which mixes the provider-neutral tool-call turn loop with the Responses wire format and OpenAI-specific choices. Kenneth asked for a design that adds Anthropic's Messages API and OpenRouter with the least ongoing compatibility work. The design (llm-provider-design.md in the repo root, untracked, with a table of every per-provider difference) splits the class into a neutral loop, one codec per API family, and provider profiles as data. OpenRouter already serves an OpenAI-compatible Responses endpoint (the prompt eval harness in tests/project_prompt uses it), so after the split it is one profile row; Anthropic becomes one codec plus a schema projection because Anthropic strict mode rejects minimum/maximum/minLength/maxLength/maxItems, which the registry schemas use. The MCP server shares only the tool registry and is untouched. This session does only the first step, the behaviour-neutral extraction; later sessions add OpenRouter and Anthropic.
