Background (from the session that started this one):
JusPrin is a fork of OrcaSlicer, with a v2 cloud server at jusprinv2.obico.io. Kenneth wants promotions on the app's Account page that the server controls, so he can change or end them without an app release.

The frame runs no scripts because of a security check made during design. On macOS (tested) and Linux (from the wxWidgets source), wxWidgets puts the app's native bridge, `window.wx`, into every frame of a web view, not only the main page. When a message arrives, it doesn't tell the app which frame sent it. A test with a bare WKWebView, set up the way wxWidgets sets one up, showed that a sandboxed frame from another site that allows scripts can post to the native handler. With `sandbox="allow-same-origin"` and no `allow-scripts`, the frame's script didn't run, and the parent page could still read the frame's height. So the box must never get `allow-scripts`.

Old app versions rely only on two things: the endpoint exists, and it returns HTML or nothing. The box's content can change freely.

Task:
Build the server-filled box near the top of Preferences › Account in JusPrin, plus the server request that fills it. Its first use is a launch-promotion banner.

What it does (Kenneth agreed to this design on 2026-11-06):
- When Account opens, the app sends a small request, `GET /v2/account_box`, to the JusPrin v2 server. It sends the sign-in token when there is one, and no token when signed out.
- The server answers with a piece of HTML, or with nothing. Nothing means no box at all: no gap and no placeholder.
- The app puts the HTML in an `<iframe sandbox="allow-same-origin" srcdoc=…>`. That frame runs no scripts, so nothing inside it can reach the app's native bridge, and links in it can't open. The box is words and pictures only.
- The Account page measures the frame's content height itself and shows the box only after it has loaded and been sized. While it loads, nothing shows.
- The box also stays hidden when the request fails, when the app is offline, and when the app runs on the person's own API key. A failed request must not break or delay the rest of Account.
- The server decides what to send for each person:
  - signed out: "Sign up today" plus the offer;
  - signed in but never paid: the offer;
  - subscribed, or has ever bought a credit pack: nothing.
- The launch offer's wording: label "LAUNCH CELEBRATION", headline "Double credits on everything", body "Until 31 Jan, every credit pack and every month of every plan gives twice the credits." For a signed-out person the body starts with "Sign up today. ".
- The look is a brand gradient (orbit → violet → bloom) with small sparkles. The server's HTML carries its own styles, because the app's CSS doesn't reach inside the frame.
