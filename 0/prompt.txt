Background (from the session that started this one):
JusPrin (OrcaSlicer fork, C++17, wxWidgets) has an in-app Agent (`src/slic3r/GUI/JusPrin/Agent/`) that sends the whole chat to a model provider on every call: Anthropic Messages (`AnthropicCodec.cpp`) or OpenAI Responses (`ResponsesCodec.cpp`), directly or through the JusPrin Cloud gateway, which forwards either format (`ProviderProfile.hpp`, `account_sign_in`). Today `AgentHost::make_agent_request` (around line 2800 of `AgentHost.cpp`) rebuilds the earlier turns on every request from the chat's messages and tool activities: assistant replies retold as text without thinking, tool calls replayed from `ToolActivity` records, app notes prefixed into user text ("JusPrin app note, not the person's words"), workspace blocks and plate pictures stripped from earlier messages, fired skills dropped from later requests. Every one of those makes the bytes differ from the request before, so provider prompt caches miss; about 70% of an Opus bill was cache writes. What the record is:
- Per chat, bound to one wire format (a chat talks to one provider family; D5: a model switch within the same format is allowed and only costs one cold cache; a switch across formats on an existing chat must be refused in `AgentHost::handle_set_chat_model` with a clear error, not silently re-rendered).
- Every item ever sent to the model, in order, with its exact wire content: the person's messages with what travelled with them (workspace block, plate picture, file report), assistant output including thinking or reasoning exactly as received (Anthropic thinking blocks with signatures; OpenAI reasoning items; check what each codec receives today and what the provider requires to be replayed), tool calls and results, fired skills, app notes.
- A lifetime per item, never an edit. Skills are visible only on the request that fired them (settled: on Anthropic via in-array `role:"system"` with `clear_at: "next_user_message"` and the beta header `mid-conversation-system-clear-at-2026-08-21`; on OpenAI as a `developer` item that has no clear and simply stays, so keep it as it is). App notes become operator-role in-conversation messages (Anthropic in-array `system`, OpenAI `developer`), kept visible, same for project and printer chats; this replaces the "JusPrin app note, not the person's words" user-text prefix. Tool results stay in their own channel.
- Pictures are stored as attachment-blob references and rendered inline at request time; image bytes never go into `state.json`.
- Stored in the chat document (`ProjectStateDocument`/`ProjectPersistence`), so a reopened project continues its chat with the same bytes.
