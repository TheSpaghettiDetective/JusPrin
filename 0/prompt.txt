Kenneth approved rollout step 3 of llm-provider-design.md: the Anthropic Messages API as a provider, on the same branch claude/provider-agent-extract. Re-read the design's per-provider table and the "Things to verify" list before starting; the Anthropic column there is the spec. Do not spend on live requests in this step.

1. AnthropicCodec (Agent/AnthropicCodec.{hpp,cpp}), an IProviderCodec. Build: endpoint https://api.anthropic.com/v1/messages; headers `x-api-key` and `anthropic-version: 2023-06-01` (add an AuthStyle for the key header, and let the profile carry the version header as a fixed header); body with `model`, `max_tokens` (required; pick 16000 and put the number in the profile), top-level `system` as an array with one text block carrying `cache_control: {type: "ephemeral"}`, `tools` with `name`, `description`, `input_schema`, `strict`, and `cache_control` on the last tool, `messages`, and `stream: true`. Omit `thinking` and `tool_choice` entirely (Opus 5.5 rejects disabled thinking and forced tool choice). Default model `claude-opus-5-5`, display name "Anthropic".
2. Messages from the transcript. Opening conversation: user and assistant text as text blocks; a replayed call as an assistant message holding a `tool_use` block ({id: call_id, name, input: parsed arguments}) followed by a user message holding a `tool_result` block ({tool_use_id, content: output_json as text}); a developer-role entry as a `{"role": "system"}` message inside `messages` (supported on Opus 5 and later, no beta header). Merge adjacent same-role messages into one message with several blocks so the sequence always alternates; do this in the codec, not the loop. This turn's user content: text blocks, image blocks `{type: image, source: {type: base64, media_type, data}}`, and PDFs as `document` blocks with a base64 source. Each TurnStep: the opaque `assistant_turn` is the response's full `content[]` array, replayed verbatim as the assistant message; the step's results go in ONE user message as `tool_result` blocks in call order, each with text content, and a result's image as an image block inside that same `tool_result`. Fired skills (the `once` items) go after the results: the picture as an image block in a user message, the text as a `{"role": "system"}` message. Mid-conversation system messages must not be first and must be followed by an assistant turn or be last; if a skill text would land in an illegal spot, put it as a text block at the end of the last user message instead. The title request: the same `kConversationTitleInstructions` as `system`, the opening conversation as messages, no tools.
3. Schema projection for strict mode. Anthropic strict rejects `minimum`, `maximum`, `multipleOf`, `minLength`, `maxLength`, and array constraints other than `minItems` 0 or 1 (verified against https://platform.claude.com/docs/en/build-with-claude/structured-outputs on 2026-10-19). Write a pure function that deep-copies a registry schema and, for every object or array property, removes those keywords and appends them to that property's `description` as text such as "(minimum 1, maximum 100)", keeping `required`, `additionalProperties: false`, `enum`, `format` and the rest. Send `strict: true` for the tools whose projected schema passes today's closed-object rule, else false. The registry is not changed: native validation stays the gate for every provider and MCP clients keep the full schemas. Unit-test the projection on a schema that uses all five keywords, and test that every registry tool's projected schema contains none of them.
4. Parse. Reset per request. Track content blocks by `index`: `content_block_start` opens a text, thinking or `tool_use` block; `content_block_delta` with `text_delta` emits TextDelta and with `input_json_delta` appends `partial_json` to that block's buffer (`thinking_delta` and `signature_delta` are kept in the block so the replayed content[] is verbatim); `content_block_stop` closes it; `message_delta` carries `stop_reason` and output usage; `message_start` carries the input usage (`input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`); `message_stop` emits TurnComplete with the reconstructed content[] (text, thinking, and tool_use with the parsed input), the calls (call_id = block id, arguments_json = the accumulated JSON), and usage; `ping` is ignored; an `error` event is Failed. Stop reasons: `end_turn` and `tool_use` complete; `max_tokens` is Incomplete; `refusal` is Failed, not retryable, with code `refusal` and the `stop_details` category in the message; `pause_turn` resends the request with the assistant turn appended (the loop already supports a step with no results if you add that; if it needs a loop change, make it the smallest one and say so). Add `cache_creation` to AgentUsage and have the Responses codec leave it 0.
5. HTTP errors: map 401/403 to invalid credentials, 429 and 529 to rate limited or overloaded (retryable), 413 to a request too large (not retryable), 5xx to service unavailable, using the profile's display name.
6. Profile, setup, configuration, page: an `anthropic` row in the table; the factory picks AnthropicCodec for the Anthropic family; Setup.tsx flips Anthropic to available with placeholder `sk-ant-…`; rebuild the bundle and run the page tests.
7. Tests. Wire tests for the Anthropic codec in their own file: body shape against a fixture request, replay of earlier calls, same-role merging, title request, attachment and skill placement, the stream parser over a canned event sequence including a tool_use with split partial_json fragments, each stop reason, and usage. The conformance test the design calls for: one scripted turn (text, two calls in one response, one failed result, an image, a fired skill, then text) driven through ProviderAgent with the Responses codec and the Anthropic codec, each fed a canned provider stream of the same meaning, asserting the two AgentEvent sequences are identical. The live smoke: a [live] case in test_provider_live.cpp like OpenRouter's, skipped without ANTHROPIC_API_KEY, metered with Anthropic's usage fields and the listed price, capped at $0.50, checking a reply, a tool call, strict on the projected schemas, and an image inside a tool_result. Written, dry-run against the local stand-in, not run live.
