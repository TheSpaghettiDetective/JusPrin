Fix a bug in the JusPrin project assistant's `slice_start` tool. Repository: C:\src\JusPrin, branch jusprin-newui. Read AGENTS.md first (especially "Error handling discipline"), and write to the user (Kenneth) in plain English.

## The bug

When a plate cannot be sliced as configured, `slice_start` with `wait: true` returns success with no explanation, and a second call with `preempt: true, wait: true` never returns.

Seen repeatedly on 2026-10-13/14 in live "journey" runs of the in-app assistant (real app, real OrcaSlicer workspace, tool calls answered by the app). The setup each time: printer preset "Bambu Lab X1 Carbon 0.4 nozzle", plate type "Smooth Cool Plate" (the harness default), one small object (tests/data/jusprin/tee_with_hole.stl), filament switched by the assistant from "Bambu PLA Basic @BBL X1C" to "Bambu PETG HF @BBL X1C" with `printer_setup`. Then:

1. `slice_start {"wait": true}` returned state succeeded with
   `{"finished":false,"handle":"t-15","started":true,"slicing":{"jobs":[],"plates":[{"estimateStatus":"none","sliced":false,...}],"running":false}}`.
   So it claims the slice started, but nothing is running and nothing was sliced, and no reason is given.
2. `workspace_inspect {"sections":["slicing"]}` confirmed: not running, not sliced.
3. `slice_start {"preempt": true, "wait": true}` stayed in state `running` and never returned. The harness waited over 20 minutes before its deadline ended the run.

In a different run of the same setup, `slice_start` instead failed twice with the message "That plate cannot be sliced as it stands", and the assistant worked out that `cool_plate_temp` is 0 for PETG HF, switched the plate type to Engineering Plate, and then sliced successfully. So OrcaSlicer does know why the plate cannot be sliced (most likely the bed temperature for that plate type is 0 for this filament); the tool sometimes surfaces it and sometimes does not. When the person's plate was set to a textured PEI plate before slicing, the same PETG setup sliced fine.
