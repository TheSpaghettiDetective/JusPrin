# Non-Bambu Printer Networking — Code Map

All paths relative to `/Users/kenneth/Projects/JusPrin/.claude/worktrees/device-simulator-printer-5dee78`.

There are **two entirely separate networking stacks** for non-Bambu printers, and they are chosen by different config keys and reached from different UI paths:

| Stack | Config key | Entry point | Used for |
|---|---|---|---|
| **A. `IPrinterAgent`** (Bambu-shaped, MQTT-emulating) | `printer_agent` (string, e.g. `"moonraker"`) | `MachineObject::connect()` → `agent-&gt;connect_printer()` | Monitor tab / device state / filament (AMS) sync |
| **B. `PrintHost`** (classic OrcaSlicer upload) | `host_type` (enum, e.g. `htMoonraker`) | `Plater::send_gcode_legacy()` → `PrintHostJob` | The actual "Print" button for non-BBL printers |

A minimal fake server must satisfy **both**, plus `/server/info` is the only endpoint both agree on.

## Minimum viable fake server

Given the above, a fake Moonraker only needs four handlers to satisfy both stacks end to end:

1. `GET /server/info` → `{"result":{"klippy_state":"ready","moonraker_version":"0.8.0","hostname":"fake-printer"}}` — **`result.klippy_state` is mandatory** or `Moonraker::test()` rejects the host (`Moonraker.cpp:90-98`).
2. `POST /server/files/upload` (multipart) → `{"result":{"item":{"path":"&lt;filename&gt;","root":"gcodes"},"print_started":false}}` — `result.item.path` is echoed straight into print start (`Moonraker.cpp:270`).
3. `POST /printer/print/start` → any 2xx; body is `{"filename":"..."}`.
4. `POST /printer/gcode/script` → any 200; body is `{"script":"..."}` (only needed for the agent path).

Optional: `GET /server/files/roots` (return 404 to skip), `GET /printer/objects/list`, `GET /server/database/item?namespace=lane_data` (for AMS sync). `/websocket` is not needed — it's `#if 0`'d out.
