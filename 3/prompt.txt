## 1. Incompatible filaments in Orca's UI

**There is no `show_incompatible_presets` preference.** The only related setting is `show_unsupported_presets` (default false, `src/libslic3r/AppConfig.cpp:347-348`). It sits in Preferences, Developer tab, as "Show unsupported presets". Its tooltip reads "Show incompatible/unsupported presets in the printer and filament dropdown lists. These presets cannot be selected." (`src/slic3r/GUI/Preferences.cpp:1984`). Changing it refreshes the sidebar filament combos (`Preferences.cpp:1073-1075`).

**The Tab's show/hide toggle is dead code.**
- `m_show_incompatible_presets` starts false, and the `flag_red`/`flag_green` bitmaps load (`src/slic3r/GUI/Tab.cpp:270-272`).
- The button is never created (`Tab.cpp:274`, commented out). Its Bind is commented out (`Tab.cpp:544-546`), and so is the tooltip update (`Tab.cpp:6944-6947`).
- So `TabPresetComboBox::show_incompatible` stays false (`src/slic3r/GUI/PresetComboBoxes.hpp:232`).

**Sidebar filament combo** (`PlaterPresetComboBox::update`):
- Incompatible presets go into `uncompatible_presets` (`PresetComboBoxes.cpp:1233-1237`).
- They are listed only when the preference is on, under "Unsupported presets" (`PresetComboBoxes.cpp:1429-1430`). Those rows are disabled (`DD_ITEM_STYLE_DISABLED` and `LABEL_ITEM_DISABLED`, `PresetComboBoxes.cpp:1381-1386`), and clicking one does nothing (`PresetComboBoxes.cpp:940-948`).
- This also applies to the slot's currently selected preset when it is incompatible. It is never appended, so the combo falls back to item 1 (`PresetComboBoxes.cpp:190-191`). That reading is inferred from the code; the comment at `PresetComboBoxes.cpp:1102-1103` says the opposite.
- The red flag is drawn by `get_bmp` (`PresetComboBoxes.cpp:660`, `:739`). In practice it only shows in the Tab combo.

**Tab combo:** it hides incompatible presets except the selected one, which shows with the red flag (`PresetComboBoxes.cpp:1692`).

**Selection policy:**
- `PresetSelectCompatibleType` has three values: `Never`, `OnlyIfWasCompatible`, `Always` (`src/libslic3r/Preset.hpp:455-462`).
- When the printer or process changes, the filament policy is `OnlyIfWasCompatible` only if the filament Tab's flag is set. Since the flag is always false, the result is `Always` (`Tab.cpp:6196-6204`).
- Under `Always`, every slot whose preset is incompatible is replaced by `first_compatible`. Preference goes to `default_filament_profile` and the same `filament_type` (`src/libslic3r/PresetBundle.cpp:5441-5456`).
- After a save, the policy is `Never`, which keeps red-flagged presets selected (`Tab.cpp:6741`).

**Can a slot keep an incompatible filament?** Through the sidebar UI, no. Selection itself has no guard: `set_filament_preset` simply assigns (`PresetBundle.cpp:5513-5520`), and so does the sidebar path (`src/slic3r/GUI/Plater.cpp:9554-9555`). So an incompatible slot survives until the next printer change. It can come from a loaded project, or from JusPrin's `select_filament_preset` used by the agent adapter (`src/slic3r/GUI/JusPrin/Workspace/OrcaWorkspaceAdapter.cpp:1410`).

**Slicing (inferred):** it does not check preset compatibility. Neither `Print.cpp` nor `PrintApply.cpp` reads `compatible_printers`, and the exported config drops both keys (`PresetBundle.cpp:4113-4114`). I found no warning tied to incompatible presets. The only near-match is the AMS-sync message "There are some unknown or incompatible filaments mapped to generic preset…" (`Plater.cpp:3621`).

## 2. How compatibility is decided (`src/libslic3r/Preset.cpp`)

**`is_compatible_with_printer`** (`Preset.cpp:809-841`), in order:
1. A preset from OrcaFilamentLibrary is rejected if the printer's name or its `inherits()` is in `m_excluded_from` (`:815-823`).
2. If `compatible_printers` is empty and `compatible_printers_condition` is set, the condition decides. A parse error counts as compatible (`:825-835`).
3. Otherwise it is compatible if any of these holds (`:837-840`):
   - it is the default preset;
   - `compatible_printers` is empty (so both empty means compatible with every printer);
   - the list contains `active_printer.preset.name` exactly;
   - or the printer is non-system and the list contains its direct parent `inherits()` (`:799-807`).
- A non-empty list overrides the condition.
- Matching uses the preset name or the parent name only. Aliases are not checked, nor grandparents (FIXME at `:803`).

**`is_compatible_with_print`** follows the same rules with `compatible_prints` (`Preset.cpp:771-791`).

**Inheritance:** a user preset with `inherits` starts from the parent's full config, `compatible_*` included, and applies its saved diff on top (`Preset.cpp:1673-1677`). The diff is all that gets saved (`Preset.cpp:691-724`). User filaments have `vendor == nullptr`, so they are always visible (`Preset.cpp:857`).

**Save-as** (`Tab::save_preset`):
- The dialog title is "Save %s as". It offers "User Preset" or "Preset Inside Project". "Detach from parent" appears only in Developer mode (`src/slic3r/GUI/SavePresetDialog.cpp:56`, `:107-121`).
- When a new filament is saved from a **system** filament whose `compatible_printers` is empty, Orca writes `[selected printer's base]`. The base is the system parent of a user printer (`Tab.cpp:6706-6714`).
- `save_current_preset` does not touch compatibility keys. It sets `inherits` to the old name for a base preset, or clears it when detaching (`Preset.cpp:2926-2932`).
- On load, a root user filament with an empty list gets the part of its name after "@" written into `compatible_printers` (`Preset.cpp:1711-1720`).

**Does a new user printer inheriting "Prusa MK4 0.4 nozzle" see existing user filaments?**
- Yes, if the filament's list contains "Prusa MK4 0.4 nozzle", through the parent rule. This is the usual result of saving from a system filament while on that printer.
- Yes, if both the list and the condition are empty.
- No, if the list names only another user printer, or a different system printer.
- A side effect: saving from a system filament that relied only on a condition pins the copy to one printer.
