Background (from the session that started this one):
JusPrin is a fork of OrcaSlicer with an in-app AI agent and an MCP server; both run tool calls through the same ToolExecutionCoordinator and workspace adapter. A test session on 2026-10-21 (its report is untracked at mcp-experience-findings.md in the repo root) found that a wrong plate id gets three different error codes from three tools, and that the MCP layer turns "a slice is already running" into workspace_unavailable, which the server instructions define as "open JusPrin and a project". A follow-up reading in the parent session found this is a pattern, not one bug: the adapter uses UnavailableOperation 69 times and InvalidArgument 59 times for very different situations; the coordinator hand-writes about 25 codes of its own (including both invalid_argument and invalid_arguments); the settings tools have a separate twelve-code table that is the only documented one; error details are filled in only two places; and neither the project prompt nor any tool description names a code, so the in-app model reads only message text, written in several voices. Kenneth asked for a sweep to decide whether to consolidate.
