Background (from the session that started this one):
JusPrin is a fork of OrcaSlicer with an in-app agent and an MCP server that share tools. On 2026-10-21 a live run through the shell harness's --manual-mcp fixture showed that `plate_layout` with `enabled: false` sets each copy's printable flag (`ModelInstance::printable`, in `OrcaWorkspaceAdapter::lay_out`), but `workspace_inspect`'s `objects` section reports `printable` from the object's own flag (`ModelObject::printable`, `OrcaWorkspaceAdapter.cpp` around `row.printable = object.printable`). So after disabling an object, the tools still see it as printable, and a model cannot tell why copies are then refused. Branch `claude/tool-error-contract` (commit 29ae944fea, unmerged) added a plate_layout check that refuses copies of a disabled object; it reads the copies' flags.
