JusPrin should interpret “print this” as a request to prepare the model, including resolving the printer, filament, and process configuration. Users should not have to request preset selection separately or know which skills to invoke. This preparation responsibility applies only when relevant to the user’s request; the agent must also answer questions and troubleshoot without unnecessarily changing the project.

**Expected behavior**

When asked to prepare or print a model, the agent should:

1. Inspect the current project, printer setup, and existing preset selections.
2. Establish which filament will be used. Distinguish software configuration from physical facts: a selected filament preset does not prove that filament is loaded. Ask about consequential unknowns when available evidence cannot resolve them.
3. Select or retain suitable printer, filament, and process presets. A preset is a saved configuration; choosing a material and choosing its corresponding preset are related but distinct decisions.
4. Preserve suitable existing settings and customizations. Preparation does not require replacing every selection with a stock preset.
5. Slice and inspect the result against the user’s requirements. Revisit selections or settings when the evidence warrants it.
6. Proceed through the application’s Send preflight and authorization boundary. A request to prepare a print must not bypass that boundary.

Material choice generally informs filament and process configuration, but these decisions can be revisited as constraints emerge.

**Where the responsibilities belong**

| Mechanism                             | Responsibility                                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Core agent instructions               | Define the agent’s general role and the obligations that apply when preparing a print.                      |
| Live context and read tools           | Supply existing selections, available presets, printer capabilities, and known physical facts.              |
| Tool descriptions and execution tools | Explain and perform preset discovery, inspection, preview, and application.                                 |
| Optional skills                       | Supply specialized judgment or procedures when existing instructions and tools prove insufficient.          |
| Application code                      | Enforce objective validity, compatibility where detectable, freshness, and consequential-action boundaries. |

The core instructions should describe a general responsibility, not special-case the literal phrase “get it printed.” Suggested wording:

> You help users with 3D printing: answering questions, preparing prints, adjusting projects, and troubleshooting problems. Follow the user’s requested scope. Questions can be answered without changing the project.
>
> When the user asks you to prepare or print a model, establish a suitable printer, filament, and process configuration. Inspect existing choices before replacing them, resolve consequential unknowns, and verify the resulting slice before reporting readiness. Starting the physical print follows the app’s authorization boundary.

**Skill design decisions**

- No new “workflow” abstraction is required. That word referred only to the steps taken to fulfill a request.
- Explicit selection, such as “use the 0.20 mm Standard preset,” should normally use the existing tools directly.
- Preset-selection guidance can live inside a relevant skill when it adds useful judgment. Selecting presets does not itself justify a dedicated skill.
- A material-selection skill remains a candidate, not an agreed requirement. Its value must be demonstrated.
- Printer, filament, and process presets should not automatically be grouped into one skill merely because all are called presets.

**Verification before calling the design reliable**

Evaluate broad preparation requests with suitable existing settings, missing setup, incompatible imported presets, and unknown loaded filament. Verify that the agent preserves valid customizations, resolves actual gaps, and checks the resulting slice.

Also test scope boundaries: “What is PETG?”, “Would PETG work here?”, and “Why did this warp?” must not automatically trigger project changes or a full preparation sequence.

These are agreed behavioral requirements and a proposed allocation of responsibilities. The current implementation’s ability to satisfy them has not been verified in this discussion.
