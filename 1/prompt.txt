**Why the password path needs a server change.** In allauth 65.21.1, an inactive account at password login turns into a plain "not signed in" 401. The body carries no code. If the app decided "deactivated" from a bare 401, it would be guessing from a status code, which the error-handling rule forbids. The way to fix it is on the server: `web_ent/jusprin/v2/sign_in.py` would refuse an inactive account at login with 400 `account_inactive`, the way its code request already does. The app would then need its branch to match `login` as well as `code/request`. That's a server change, so it needs Kenneth's go-ahead.
