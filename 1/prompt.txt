Bug: the printer panel (src/slic3r/GUI/JusPrin/PrinterSetup/PrinterPanel.cpp, build_runtime) creates a fresh in-memory Agent::ProjectPersistence (storage.in_memory = true) every time it opens. The AgentHost takes tool action ids from that document (AgentHost.cpp: set_action_id_allocator -> ProjectStateDocument::allocate_action_id, which returns "t-1", "t-2", ...). Since 7852470aff the panel also installs the shell's version callbacks (host.tools().set_version_callbacks(version_before, version_after) in ShellController.cpp). version_after calls ProjectAutosave::record_agent_operation, which writes operations/<action_id>.json into the PROJECT's permanent version store. ProjectVersionStore::record_operation refuses an existing file ("operation version record already exists"). Result: the second versioned tool call (printer_change, or settings_apply_patch) from any later panel opening on the same project gets the same id "t-1". The change goes through, but the tool reports local_save_failed "The action ran, but its changes couldn't be saved. Check the project before trying again." The model then tells the person that a successful change failed. The panel's ids may also collide with the project agent pane's own "t-N" ids in the same store.

Reproduced 2026-10-14 with `JusPrinShellHarness --printer-setup`: after the existing check nozzle_panel_change_keeps_the_dropped_edit_in_history, a second call_in_panel(named, "printer_change", {nozzle 0.6}) on the same project changed the nozzle, dropped the unsaved printer_notes edit, and failed with that message; the log showed "Could not save after Agent action: operation version record already exists".
