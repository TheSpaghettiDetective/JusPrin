Background (from the session that started this one):
JusPrin is a fork of OrcaSlicer with its own UI under `src/slic3r/GUI/JusPrin/`. It has an app guide in `docs/guide` that people read (on GitHub and in the app under Help › JusPrin guide…) and that the in-app AI reads as skills. Before each release the guide is brought in line with the app by one command, `scripts/check_guide.py --ask-ai`: it drives the built app through each page's screens with the shell harness, retakes the pictures, rebuilds the AI's copy of each page, checks every quoted on-screen label against the source, and asks the model each page's questions. The steps are in `docs/guide/README.md` under "Before a release", and one line under "Documentation" in `AGENTS.md` points to it.

All of this is on branch `claude/guide-window` (pushed to origin; not merged into `jusprin-dev`; no pull request). Another session is writing six more guide pages from that branch on `claude/hungry-murdock-3137cd`, and it also touches `docs/guide/README.md` and possibly `AGENTS.md`.

The problem this task solves: an agent making a release has no reason to open either of those files, so the guide step can be forgotten. The release steps are written only in the comment at the top of `.github/workflows/jusprin_release.yml`, and that workflow already teaches by refusing: its `prepare` job has a step "Require the release notes" that stops with a message saying which file to write when `src/slic3r/GUI/JusPrin/Packaging/release-notes/<version>.md` is missing. The version comes from `src/slic3r/GUI/JusPrin/Updates/Version.hpp` through `src/slic3r/GUI/JusPrin/Packaging/release.mjs`, whose checks are tested without GitHub by `release.test.mjs` beside it.
