JusPrin 2.1.0 can run its AI chats on a model on your own computer, lets AI add holes and parts to your models, and tells you clearly what to do when your own AI account refuses a request.

## New

- **AI on your own computer.** Chats can run on a model in Ollama or LM Studio, with no account and no credits. Set it up in Preferences › BYOAI › A model on this computer: press Find models, pick one, and press Use this model. JusPrin checks that the model can use the app's tools and has a context of at least 32k. It then shows under "On this computer" in each chat's model menu. Web search is not available for these chats, and a model that cannot see pictures is sent none. When Ollama or LM Studio refuses, for example because the model was deleted, JusPrin shows its words.
- **AI can add holes and parts.** Ask AI for a screw hole, a slot, a peg or a lip, and it adds boxes or cylinders to your object, as solid parts or as holes. One Undo removes them. Asked for text or a logo, AI gives you the steps to add it yourself; a logo must be an SVG file.
- **AI can change your printer's hardware settings,** such as the bed size, the nozzle and the number of extruders. Before, it told you to change them by hand.
- **More printers connect from the printer chat.** For a Flashforge printer in LAN Only mode, PrusaLink with a user name and password, or Repetier, the chat opens a form that asks for the serial number, access code, login or printer name. What you type goes only to the printer; AI does not see it. Only UltiMaker still has to be set up in the printer settings window.
- **Home tells you when a new version is out.** A card at the top of Home's right column says which version is available. See what's new shows the release notes, Open download page opens the download page, and you can choose Remind me tomorrow or Skip this version.
- **OrcaSlicer's message boxes go into the chat.** In the JusPrin view, messages such as a failed printer connection or a refused print job now show in the project's chat instead of in a box over the app. Switching printer, filament or process while settings are changed no longer asks "Transfer or discard changes": JusPrin saves a version of the project first, so Version history keeps your changes, and the chat says which profiles the settings now follow.
- **Clearer messages when your own AI account refuses.** With your own key for OpenAI, OpenRouter or Anthropic, JusPrin now says when the account is out of credits, when the key is not allowed, or when the chat is too long for the model. When the service explains a refusal itself, JusPrin shows its words, for example "OpenRouter says: …". When the service is down or overloaded, JusPrin says the service is having trouble right now, instead of "Something went wrong on our side".
- **About 200 more sentences are translated,** including the titles of AI's actions in the chat, setting values in the Changes list, and the printer chat's first message.

## Fixed

- On Windows, quitting JusPrin crashed when error reports were turned on.
- On Windows in German and other languages, Ask AI about filament settings opened an empty chat with "Something went wrong on our side".
- On Windows in French, Spanish or Portuguese, a chat whose title had an accented letter, such as "Problème", failed to send.
- A chat whose reply stopped during a web search could not be continued: every next message failed.
- When AI switched to another printer with more filaments than that printer takes, the printer was switched and then the setup failed half done. It is now refused before anything changes.
- AI could end a chat with "cannot run (invalid_arguments)" after writing a note that was too long. It is now told which text was too long and the limit, and shortens it.
- Import printers from OrcaSlicer stayed on "Importing…" with every button greyed out after Cancel on the unsaved-changes question.
- On Linux with Wayland and an Intel graphics card, the Preview, Device and Project tabs could freeze.
- On Windows, when the 3D view could not start OpenGL, JusPrin could crash or show an empty 3D view. It now says which graphics card it found and what to check.
- In Preferences › BYOAI, when connecting an outside AI app such as Claude Code failed, the message gave no next step. It now says to copy the command and run it yourself, with a Copy button.
- Many messages written for AI were shown to you instead, such as "A hello handshake is required". Typing a message and then opening an earlier chat lost what you typed. Resume on an earlier chat failed after a slice. "Revert to here" opened a "Revert failed" window, and pressing the slice button twice opened "Couldn't slice".
- A picture in a format AI cannot read, such as a HEIC phone photo renamed to .jpg, is now refused when you attach it, with "This file type can't be read by AI."
- A project whose chats were saved by a newer JusPrin now says so in the chat, instead of showing no chats.

## What JusPrin now sends

- **Error reports and crashes** now carry your JusPrin account number when you are signed in, or else the random number this install made on its first start, so we can tell how many people a problem hits. Your email is not sent. Reports are still sent only when you press Report to JusPrin team, or when you have turned on automatic reports.
- **A chat on a model on your computer** is sent only to the address you entered in Preferences, including the request that names the chat.

## Downloads

- **Windows (64-bit):** the installer, or the portable .zip, which runs without installing.
- **Mac:** one disk image for Macs with Apple silicon and Intel Macs.
- **Linux (64-bit):** an AppImage, built on Ubuntu 24.04. Make the file executable, then run it.
- **SHA256SUMS.txt** lists each file's checksum.
